================================================================================
  CHATWOOT CUSTOM — COLLEAGUE / CLIENT SETUP GUIDE
  Read top to bottom. Each section is a single coherent step.
================================================================================

WHAT THIS IS
------------
A fork of Chatwoot (open-source customer support platform) with two custom
additions:

  1. A "Voice Agent" section inside each web-widget inbox's Configuration
     tab. The admin pastes their ElevenLabs (or other provider) Agent ID +
     optional API Key — visitors then get a phone button next to the chat
     input that starts a real-time voice call with that agent.

  2. Voice call transcripts auto-post into the same Chatwoot conversation,
     so agents see what the visitor said and what the AI answered as normal
     message bubbles in the dashboard.


PREREQUISITES (one-time, on the colleague's machine)
----------------------------------------------------
- Docker Desktop      (Windows / Mac / Linux)        https://docker.com
- Git                 (to clone the repo)
- 8 GB RAM free during first build (Vite bundle is large)
- 10 GB free disk space


--------------------------------------------------------------------------------
OPTION A — RUN FROM PRE-BUILT IMAGE  (fastest, no compile)
--------------------------------------------------------------------------------

Use this when you've already pushed the image to a registry (Docker Hub, GHCR,
your private registry, etc.) so your colleague doesn't need to build anything.

  1. Pull the image
     ─────────────────
     docker pull <your-registry>/chatwoot-custom:<tag>

     Example with Docker Hub:
        docker pull jatin71/chatwoot-custom:latest

     Example with GitHub Container Registry:
        docker pull ghcr.io/jatinn71/chatwoot-custom:latest

  2. Clone the repo (you still need docker-compose.yaml + .env)
     ─────────────────
     git clone <your-repo-url>
     cd chatwoot-custom-master

  3. Copy the env template
     ─────────────────
     cp .env.example .env
     # then edit .env — see "ENV VALUES" section below

  4. Make docker-compose use the pulled image
     ─────────────────
     Open docker-compose.yaml, change the `image:` line under the rails /
     sidekiq services to whatever you pulled in step 1, e.g.:

       image: jatin71/chatwoot-custom:latest

     (Remove or comment out any `build:` block under those services so
     compose doesn't try to rebuild from source.)

  5. Start everything
     ─────────────────
     docker compose up -d

  6. Wait ~60 seconds, then open  http://localhost:3000
     First-run will show an account-setup screen. Create the admin user,
     log in, then jump to "POST-INSTALL: WIRE UP VOICE AGENT" below.


--------------------------------------------------------------------------------
OPTION B — BUILD LOCALLY FROM SOURCE  (slower, no registry needed)
--------------------------------------------------------------------------------

Use this when there is no pre-built image or your colleague wants to modify
code first.

  1. Clone the repo
     ─────────────────
     git clone <your-repo-url>
     cd chatwoot-custom-master

  2. Copy the env template
     ─────────────────
     cp .env.example .env
     # edit .env — see "ENV VALUES" section below

  3. Build the image (takes 5–15 min depending on machine)
     ─────────────────
     ./build.sh

     This runs `docker build` with the right memory settings. If it fails
     with exit code 139 (SIGSEGV) you need a bigger machine or you can
     uncomment the "no-minify" fallback line in Dockerfile.

  4. Start everything
     ─────────────────
     docker compose up -d

  5. Wait ~60 seconds, then open  http://localhost:3000


--------------------------------------------------------------------------------
ENV VALUES — what to put in .env
--------------------------------------------------------------------------------
Open .env in any text editor and fill these:

  FRONTEND_URL=https://your-public-domain.com
      Public URL of the Chatwoot install. Localhost is fine for testing
      (http://localhost:3000), but voice/mic features only work on HTTPS
      origins outside localhost. For live testing behind a tunnel use
      ngrok / cloudflared / your domain.

  SECRET_KEY_BASE=<long random string>
      Generate one with:
         docker run --rm chatwoot/chatwoot:latest rails secret
      Paste the output here. NEVER reuse the dev value in production.

  POSTGRES_PASSWORD=<choose a strong password>
      Used by the bundled postgres container. Match what's in
      docker-compose.yaml.

  REDIS_PASSWORD=<choose a strong password>
      Same idea for redis.

NOTE: Voice-agent settings (ElevenLabs API Key, Agent ID, etc.) are NOT
configured in this file anymore. They live per-inbox in the Chatwoot
dashboard — see the next section.


--------------------------------------------------------------------------------
POST-INSTALL — WIRE UP THE VOICE AGENT (5 minutes)
--------------------------------------------------------------------------------

  1. Log in to the dashboard
     ─────────────────
     http://localhost:3000  (or whichever FRONTEND_URL you set)

  2. Create a Web Widget inbox if you don't have one yet
     ─────────────────
     Settings → Inboxes → "Add Inbox" → Website → fill in the website name
     and URL → finish.

  3. Open the inbox's Configuration tab
     ─────────────────
     Settings → Inboxes → <your inbox> → "Configuration" tab.
     Scroll down to the "Voice Agent" section.

  4. Fill in the voice agent
     ─────────────────
     - Toggle "Enable Voice Agent" → ON
     - Provider     :  elevenlabs   (only one supported right now)
     - API Key      :  leave BLANK if the agent is "Public" in ElevenLabs.
                       Paste the key only if the agent is "Private" —
                       requires `convai_write` permission on the key.
     - Agent ID     :  copy from your ElevenLabs dashboard URL:
                       https://elevenlabs.io/app/conversational-ai/agents/agent_XXXXXXX
                                                                          ^^^^^^^^^^^^^
                       Paste the agent_XXXXXXX portion.
     - Save Voice Agent Settings.

  5. Make sure your ElevenLabs agent itself is configured
     ─────────────────
     In ElevenLabs Agents page, open your agent and confirm:
        - Voice is assigned (otherwise the agent will be silent)
        - First Message is non-empty (e.g. "Hi, how can I help?")
        - System Prompt is non-empty
        - For Public access:  Security tab → "Allow public access" ON


--------------------------------------------------------------------------------
EMBEDDING THE CHAT WIDGET ON THE CLIENT'S WEBSITE
--------------------------------------------------------------------------------
Works on ANY website tech stack — React, Vue, Angular, Next.js, WordPress,
Shopify, plain HTML — because it's a single async <script> tag.

  1. In the dashboard, go to:
     Settings → Inboxes → <your inbox> → "Configuration" tab.

  2. Copy the script block under "Messenger Script".
     It looks like:

       <script>
         (function(d,t) {
           var BASE_URL="http://localhost:3000";
           var g=d.createElement(t),s=d.getElementsByTagName(t)[0];
           g.src=BASE_URL+"/packs/js/sdk.js";
           g.async = true;
           s.parentNode.insertBefore(g,s);
           g.onload=function(){
             window.chatwootSDK.run({
               websiteToken: 'YOUR_WEBSITE_TOKEN',
               baseUrl: BASE_URL
             })
           }
         })(document,"script");
       </script>

  3. Paste that block right before </body> on every page of the client's
     site. That's it. The chat bubble appears in the bottom-right corner.

Where to paste depending on stack:
  - Plain HTML / WordPress / Shopify : paste in footer.html / theme footer.
  - React / Next.js : paste inside <Head> or use next/script in _document.
  - Vue / Nuxt : paste in public/index.html or nuxt.config head.scripts.
  - Angular : paste in src/index.html before </body>.


--------------------------------------------------------------------------------
COMMON TROUBLESHOOTING
--------------------------------------------------------------------------------
> Call button doesn't appear in the widget
  Toggle off → save → toggle on again → save. Then bubble close + reopen.
  The widget re-fetches voice config on every bubble open.

> Call connects then disconnects in ~3 seconds
  ElevenLabs quota exceeded. Check https://elevenlabs.io/app/usage.
  Free tier gives ~15 min of Conversational AI per month. Upgrade or wait.

> "missing_permissions: convai_write" in rails logs
  Your ElevenLabs API key doesn't have ElevenAgents/Convai write permission.
  ElevenLabs dashboard → API Keys → edit your key → enable
  "ElevenAgents → Write" → save → re-paste into Chatwoot dashboard.

> Voice transcript not appearing in conversation
  Check rails logs:   docker compose logs rails | Select-String voice_transcript
  Successful POST should return 200. If 500, paste the error.

> Browser shows "WebRTC negotiation timed out"
  Already mitigated — we use the <elevenlabs-convai> embed which speaks
  ElevenLabs' current LiveKit protocol. If it ever resurfaces, rebuild
  with `./build.sh` to refresh the bundle.

USEFUL COMMANDS
--------------------------------------------------------------------------------
docker compose up -d                 # start everything in background
docker compose down                  # stop and remove containers
docker compose logs -f rails         # tail rails logs (Ctrl+C to exit)
docker compose logs rails | Select-String VOICE-AGENT
                                     # PowerShell: find voice-agent log lines
docker compose restart rails         # restart rails after editing volumes
docker compose exec rails rails c    # open a rails console
docker compose exec rails bash       # shell into the rails container
